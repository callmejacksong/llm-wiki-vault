## 核心摘要

这份 Gemini API 中文文档剪藏从清晰指令、示例、上下文和生成参数入手，再讨论 Gemini 3 与复杂智能体的提示方法。核心是用明确任务和一致结构表达预期，结合具体用例反复试验，并在事实检索、计算等任务中使用合适工具。

1. **定义输入、限制和输出。** 输入可表现为问题、任务、待处理实体或待续写内容。说明长度、内容边界和格式；可用输出前缀引导模型续写。简单 JSON 可用提示表达，复杂 JSON 架构则推荐使用 Gemini API 的结构化输出功能。
2. **用少样本示例塑造模式。** 示例应具体、多样，且保持标签、空格、换行和分隔符一致。示例既能约束格式，也能表达偏好，例如在长短解释中选择简短版本。文档强烈建议包含少样本，但同时要求实验确定数量，提醒示例过多可能使输出过度贴合示例。
3. **补足有依据的上下文。** 路由器排障示例表明，提供设备说明并限定依据，可以把泛化回答变成针对具体状态的回答。长上下文先给资料，再在末尾提出具体问题，并用过渡语将问题锚定到资料；关键行为限制和角色规则则优先放入系统指令或提示开头。
4. **分解、串联或并行汇总。** 复杂任务可拆成多个提示，前一步输出作为下一步输入；对不同数据部分独立处理后汇总，适用于可分离的子任务。
5. **迭代提示与参数。** 可改变措辞、将任务改写为等价形式、调整示例和上下文顺序。输出词元上限、温度、topK、topP 和停止序列影响生成过程；文档提醒不同模型可用参数不同。示例中的分类改写仍带解释前缀，不能当成严格格式遵从的证明。
6. **让工具支持事实与计算。** 文档介绍使用 Google 搜索接地处理最新或冷门事实，使用代码执行处理算术、计数和计算。这是工具用途说明，不是“启用后保证无幻觉”的实验证据。
7. **按模型与任务配置推理。** Gemini 3 部分强调直接简洁、结构一致、清楚引用各模态。文档称 Gemini 2.5 和 3 系列具有内部思考能力，通常无需要求输出详细推理过程；深度智能体则可显式配置依赖分析、诊断、适应、恢复、权限判断和沟通行为，并权衡准确率、时延与词元成本。

## 知识冲突

- **强规划模板与过度思考：** 本文的深度智能体模板要求行动前广泛分析；[[anthropic-prompting-best-practices]] 提醒强模型可能过度探索，应减少笼统的反复思考要求。模型、任务与成本边界不同，见 [[Prompt_Engineering]]。
- **拆分任务的默认程度：** 本文建议复杂任务拆提示并串联，与课程经验接近；Anthropic 文档偏向在中间验收或固定管线需要时显式拆分。原有差异及其条件继续保留。
