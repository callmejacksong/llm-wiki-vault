## 核心摘要

课程把提示工程比喻为“用自然语言编程”：通过明确任务、角色、上下文、输出格式和约束，减少模型猜测需求的空间。提示的长度本身不是质量指标，关键在于信息是否与任务相关。讲者把方法从文本生成延伸到可调用工具、执行动作的 Agent 场景，但演示主要围绕文本任务。

| 时间 | 方法 | 要点与案例 |
| --- | --- | --- |
| 1:44–4:06 | 定义任务 | 说明要完成什么、面向谁、交付什么；相同模型会因输入清晰度不同而产生不同结果。 |
| 4:07–7:04 | 降低输入成本 | 讲者推荐语音口述来提供更多必要细节，演示自动整理标点与重复词；这段含合作工具推广。 |
| 7:05–10:39 | 理解上下文 | 应用可能加入历史、文件与工具信息；用户刚输入的句子不一定是模型看到的全部内容。 |
| 10:40–14:31 | 引导而非只下命令 | 明确角色、受众、语气、长度和格式。客服回复示例补充承认问题、调查状态、下一步与署名。 |
| 14:32–18:09 | 少样本提示 | 给输入输出对，让模型参照格式与模式。工单标题案例规定单行、“区域＋简述”和长度，避免返回多个候选。 |
| 18:10–20:04 | 逐步推理 | 用于数学、逻辑和规划；讲者承认现代推理模型可能已经自动处理，未现场展示算术对照实验。 |
| 20:05–22:03 | 结构化输出 | 给出目标 JSON 等形状，并指定只返回该格式，便于后续代码读取。 |
| 22:04–24:18 | 约束与否定要求 | 指定长度、语气、禁用表达与内容边界；休假自动回复案例要求直接列出日期与紧急联系人。 |
| 24:19–25:21 | 迭代优化 | 在已有草稿上反馈“缩短”“更正式”“只聚焦某点”等具体偏差，逐步收敛。 |
| 25:22–29:12 | 访谈式提示 | 先给目标，让模型逐项追问背景、受众、指标和边界，信息足够再生成；用户可以停止提问。 |
| 29:13–31:21 | 持续设定与当次任务 | 讲者用 system/user prompts 区分持续角色、规则与单次请求，并以自定义指令演示风格设定。 |
| 31:22–32:15 | 提示链 | 将复杂任务拆成可检查的阶段，例如“大纲→正文→SEO 元数据”，前一步输出进入下一步。 |
| 32:16–33:16 | 评审与修改 | 请求按清晰度、完整性评分，并提出最重要的改进；讲者建议新会话评审，但未给对照数据。 |
| 33:18–35:03 | temperature | 讲者用低温偏稳定、高温偏多样解释采样调整；未给具体模型参数范围或确定性保证。 |
| 35:04–37:28 | 常见错误与练习 | 避免任务含糊、一次塞入过多任务、缺少背景和示例、格式不清，以及假定模型记得所有历史。 |

## 可复用的实践顺序

以下是依据课程整理的操作顺序，并非视频中的逐字模板：先说明任务、受众和交付格式，再补充必要事实与示例；不知道缺什么时先让模型访谈；复杂工作设置阶段检查点；得到草稿后用具体反馈和评审标准改进。新会话或长线程中重述关键事实。
