## 核心摘要

Tech With Tim 通过客服回复、工单标题、JSON 产品比较和社交媒体文案等示例，说明如何用明确的角色、背景、输出格式和迭代反馈，减少模型对用户意图的猜测。提示质量取决于有效信息，篇幅长本身不构成质量保证。

| 时间 | 方法 | 主要内容与用途 |
| --- | --- | --- |
| 01:44–04:06；10:40–14:28 | 明确任务与场景 | 指定角色、受众、语气、输出格式和约束；例如客服回复应包含行动承诺和长度要求。 |
| 07:08–10:34；36:03–36:25 | 理解实际上下文 | 界面可能向模型注入系统规则、历史和文件；新会话或长会话中应重述关键事实。 |
| 14:35–18:04 | 少样本提示 | 给输入与输出配对示例，展示工单标题等任务的格式与边界，避免模型自行增加备选项。 |
| 18:13–19:58 | 逐步推理 | 对未默认推理的模型，逐步分析可能有帮助；讲者也承认现代推理模型常已具备相应行为。 |
| 20:08–21:57 | 结构化输出 | 指定 JSON、表格等结构和字段，减少解释性文字，便于程序处理；视频展示不等于格式永远有保证。 |
| 22:04–24:16 | 约束与禁止项 | 明确长度、语气、内容边界及避免的套话，缩小结果空间。 |
| 24:19–25:15 | 迭代改进 | 基于已有草稿提出“更短”“更正式”等具体反馈，逐步接近目标。 |
| 25:26–29:00 | 访谈式提示 | 先给目标，再让模型逐题询问受众、背景和指标；信息足够后停止提问并生成产物。 |
| 29:16–32:10 | 系统规则与提示链 | 区分常驻行为规则和单次任务；复杂工作可拆为大纲、正文、元信息等阶段，并核验中间产物。 |
| 32:16–34:58 | 评价与生成参数 | 按标准评价草稿后再修订；讲者用低温度偏稳定、高温度偏多样的经验解释采样设置。 |

## 实践流程

先定义目标和交付格式；若背景不清楚，先进行有限澄清；补入相关示例和约束，生成初稿；按明确标准检查，针对具体缺口修订。复杂任务可拆步骤，但每一步都应保留下一步需要的事实与产物。

## 来源与证据边界

- 原始元数据标注发布于 2026-03-11，正文字幕覆盖 00:00–37:28，存在自动转录误词；本摘要依据完整正文和章节理解，不修改原始转录。
- 04:14–07:04 的 Wispr Flow 口述输入演示含合作推广，讲者披露商业关系；“最好”等产品评价属于个人推荐，本次没有独立验证，也不单独为推广产品建页。
- 26:40–28:59 的四天工作制场景中，讲者明确说自己在编造演示背景；其中的生产率、收入和满意度变化不是实证研究结论。
- 关于模型只是在预测文本、推理仅由外层编排实现的说法，是讲者的入门简化解释，课程没有给出架构证据。示例 JSON 也不等于正式 JSON Schema；不能从口头演示推导严格的类型或格式保证。
- 低温度与确定性的类比、换会话并伪称人工作者能改善评价偏差等，均为讲者经验说法，缺少课程内对照证据；不作为已验证的通用规律。
