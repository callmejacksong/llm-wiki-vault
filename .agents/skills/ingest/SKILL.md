# 导入资料

遵循仓库根目录 `AGENTS.md` 的读写边界、页面规范、索引与日志约定。`01-原始资料/` 始终只读，处理成功后也不移动原文件。

## 选择资料

- `$ingest`：扫描 `01-原始资料/`，默认排除 `01-原始资料/99-归档/`。读取 `02-wiki知识库/03-摘要/` 的 YAML `sources` 字段，按仓库相对路径精确匹配已导入资料，不以摘要文件名或简单子串匹配判断。
- 已有完整摘要、相关页面和索引的来源默认跳过；仅有占位摘要或上次导入未完成的资料继续处理，不能因出现 `sources` 路径就判定成功。
- `$ingest "01-原始资料/路径/文件.md"`：只处理指定文件。若已有摘要，增量更新已有页面；用户明确指定的历史归档文件可以只读读取。
- 路径含空格或中文时作为完整路径处理。路径不存在时报告，不擅自替换成同名材料；指定目录时按批量规则处理其下文件。
- 开始前读取 `02-wiki知识库/index.md` 与相关现有页面，避免重复创建实体、概念和摘要。

## 提炼与整合

1. 完整读取 Markdown 或文本；长文可以分段读取。PDF 使用可用的文本提取工具，必要且可用时使用 OCR。无法读到正文则报告原因和待处理项，不生成推测摘要，也不将其记为已导入。
2. 提炼核心主旨、重要实体、重要关键概念、可验证的关键结论，使用简体中文并保留必要原文术语， 提取和这个一篇文章中涉及的核心的几个关键实体， 关键人物、公司和产品，重要概念、框架和方法论，理想情况下一篇文章只提取那么1-3个关键实体，1-2个重要概念、框架和方法论。
3. 在 `02-wiki知识库/03-摘要/` 新建或更新 `source-slug.md`。记录准确的 `sources` 路径，包含 `## 核心摘要` 与 `## 关联连接`。
4. 在 `02-wiki知识库/02-实体/`、`02-wiki知识库/01-概念/` 增量合并关联知识。保留已有来源，在相关页面补充来源摘要的反向链接。命名规则沿用 `AGENTS.md`，不要给同一概念另起别名建页。
5. 遇到知识冲突，在相关页面的 `## 知识冲突` 中并列观点、出处和适用条件，继续处理其他资料，最终报告待判断项。
6. 更新 `02-wiki知识库/index.md`，验证新增或修改页面的 YAML、来源路径和双链目标；将本次实际完成、跳过、冲突和失败项目追加到 `02-wiki知识库/log.md`，动作使用 `ingest`。

来源页示例（路径、日期、链接均须替换为实际值）：

```markdown
---
title: "资料标题"
type: source
tags: [来源, 提示工程]
sources: ["01-原始资料/01-文章/文件名.md"]
last_updated: YYYY-MM-DD
---

## 核心摘要

有来源支持的主要结论。

## 关联连接

- [[Prompt_Engineering]] — 相关概念
```

如用户明确要求只预览或完全只读，输出拟议内容与变更清单，不写页面或日志。正常导入结束后报告变更页面与未完成项，保留所有源文件原位。
