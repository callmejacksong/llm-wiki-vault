# 知识库健康检查

遵循仓库根目录 `AGENTS.md`。默认检查并报告，不改知识页；用户已经要求修复时，完成有依据的修复，无需再次确认。

## 检查范围与方法

从仓库根目录枚举 `02-wiki知识库/` 下的 Markdown 文件，可使用 `rg --files 02-wiki知识库` 或当前环境的文件工具。`index.md` 和 `log.md` 为管理文件，不要求知识页 frontmatter 或关联章节。

1. **索引一致性**：比对 `02-wiki知识库/index.md` 和全部知识页，报告缺少索引、重复条目、索引指向不存在页面的情况。
2. **双链解析**：提取正文中的 `[[目标]]`、`[[目标|别名]]`、`[[目标#标题]]`、`[[目标#^块标识]]` 和嵌入语法 `![[附件]]`。跳过代码块与行内代码中的示例。先去别名，再拆分标题/块标识；`[[#标题]]` 是本页引用，不是缺失文件。
3. **目标解析**：支持带或不带 `.md` 的名称、相对路径与仓库内路径。按 Obsidian 规则在 vault 中解析，必要时只读枚举 `01-原始资料/`、`99-附件/` 的文件名以校验目标，不修改它们；同名多个目标标为歧义，不能任意选一个。附件不是知识页，不计入孤儿统计。文件存在但标题或块不存在时单独报告锚点问题。
4. **图谱连接**：只以知识页之间的链接统计关联，排除自引用、`index.md` 和 `log.md` 的引用。分别报告无其他知识页入链的孤儿页，以及缺少 `## 关联连接` 或没有有效出链的页面，避免索引掩盖孤岛。
5. **元数据与来源**：检查 YAML 能否解析，`title`、`type`、`tags`、`sources`、`last_updated` 是否符合 `AGENTS.md`；验证 `sources` 中的原始资料路径是否存在。只靠文件名无法确认历史资料对应关系时，标为待核实。
6. **知识冲突**：汇总 `## 知识冲突` 区块；检查相关页面时遇到的新矛盾标为候选冲突并给出双方出处。区分已标注冲突和本次候选冲突，不声称穷尽了所有语义矛盾。

## 报告与修复

输出检查范围、各类问题数量、来源页面和具体目标，给出可执行的修复建议。区分死链、锚点缺失、歧义、孤儿页、索引遗漏、元数据错误、失效来源及知识冲突；工具限制或未检查部分应明确说明。

- 用户仅要求体检：输出报告后追加 `lint` 日志，记录发现情况，不修改知识页。
- 用户明确要求完全只读：连日志也不写。
- 用户已要求修复：修复可确定的索引遗漏、错误链接或元数据；不凭空生成页面、删除观点或猜测来源来消除报告项。保留冲突双方与出处，对无法确定的修复报告待处理原因。
- 修复后复查受影响页面与链接，追加 `lint` 日志记录实际修复和未解决项。`01-原始资料/` 仍然只读。
